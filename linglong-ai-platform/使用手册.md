## 一、系统概述

灵龙AI智能平台（LingLong AI Platform）是一个AI驱动的全生命周期软件开发平台，集成多厂商大语言模型（LLM）、MCP协议工具链、多智能体协作工作流。

**核心功能模块（13个）**：

| 编号 | 模块 | 前端路由 | 核心能力 |
|------|------|---------|---------|
| 1 | 登录/注册 | `/login` `/register` | 用户认证、角色校验、密码重置 |
| 2 | 应用广场 | `/` | 功能入口导航、应用搜索与筛选 |
| 3 | AI对话助手 | `/chat` | 多模型对话、RAG增强、文档问答、SSE流式 |
| 4 | 知识库管理 | `/knowledge` | 文档上传向量化、语义搜索、分类管理 |
| 5 | 智能体中心 | `/agents` | 11个Agent管理、执行、配置 |
| 6 | Agent智能开发 | `/codeflow` | 6步工作流、SSE实时进度、代码生成 |
| 7 | 项目中心 | `/projects` | 项目CRUD、代码浏览、ZIP下载 |
| 8 | MCP工具中心 | `/mcp` | 7类内置工具执行、外部工具管理 |
| 9 | 模型管理 | `/settings` | LLM厂商配置、数据库配置、安全设置 |
| 10 | AI图片生成 | `/image-generation` | 文生图、图生图 |
| 11 | AI简历助手 | `/resume` | 简历生成、测评、优化 |
| 12 | 个人中心 | `/profile` | 个人信息、密码修改 |
| 13 | 用户管理 | `/admin/users` | 管理员用户CRUD |

## 二、系统架构与部署

### 2.1 微服务架构

```
浏览器 (linglong-ui:3000)
        │
        ▼
API网关 (linglong-gateway:8080)
        │
   ┌────┼────────┬──────────┐
   ▼    ▼        ▼          ▼
用户服务  Agent服务  LLM核心   MCP服务
:8081    :8085     :8084     :8083
   │      │         │          │
   └──────┴────┬────┴──────────┘
               ▼
  MySQL(3306) + PostgreSQL(5432) + Redis(6379)
```

### 2.2 服务清单

| 服务 | 端口 | 技术栈 | 职责 |
|------|------|--------|------|
| linglong-gateway | 8080 | Spring Cloud Gateway | 统一入口、路由转发、CORS、限流 |
| linglong-user | 8081 | Spring Boot + MyBatis Plus | 用户认证、个人中心、管理后台 |
| linglong-agent | 8085 | Spring Boot + LangChain4j | Agent执行、工作流编排、项目管理 |
| linglong-llm-core | 8084 | Spring AI + pgvector | LLM对话、RAG检索、向量存储 |
| linglong-mcp-server | 8083 | Spring Boot + JPA | MCP工具注册、发现、执行 |

### 2.3 外部依赖

| 依赖 | 地址 | 用途 |
|------|------|------|
| MySQL 8.0 | 8.137.117.129:3306/linglong | 用户、配置、对话历史 |
| PostgreSQL 14+ | 8.137.117.129:5432/linglongpg | 向量知识库(pgvector) |
| Redis 6+ | 8.137.117.129:6379 | Token缓存、会话上下文 |
| MinIO | 8.137.117.129:9000 | 对象存储 |

### 4.6 Agent智能开发（CodeFlow）

**页面路径**: `/codeflow`

**UI布局**:
- 顶部：模型选择器（下拉列表，含厂商分组和模型标签）
- 左侧(约60%)：需求描述输入区（Markdown编辑器）+ 参考文件上传区
- 右侧(约40%)：6个步骤卡片（垂直排列，实时状态更新）
- 底部：启动智能开发/停止/重置/打包下载按钮
- 结果展示区：每步骤完成后显示输出（代码文件树+预览）

**工作流步骤**:
```
步骤1: 需求分析 → 步骤2: 领域建模 → 步骤3: 架构设计
→ 步骤4: 代码生成 → 步骤5: 代码审查 → 步骤6: 测试生成
```

**步骤状态**:
- `pending` — 灰色，等待执行
- `running` — 蓝色旋转动画，正在执行
- `completed` — 绿色打勾，已完成
- `failed` — 红色叉号，执行失败

### 6.3 通用接口测试检查点

每个接口都应验证：

1. **正常请求** — 正确参数返回200和数据
2. **参数校验** — 缺少必填参数返回400
3. **参数类型** — 错误类型参数返回400
4. **认证校验** — 需要Token的接口，无Token返回401
5. **资源不存在** — 查询不存在的ID返回404
6. **响应格式** — 统一格式: `{ code, message, data, timestamp }`
7. **响应时间** — 非AI接口应在2秒内响应
